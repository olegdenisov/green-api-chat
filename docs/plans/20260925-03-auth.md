# Этап 3: Auth (логин/логаут)

## Overview

- Третий из 6 этапов (см. `docs/plans/20260923-telegram-chat-design.md`, «Этапы»).
- Пользователь вводит `idInstance`, `apiTokenInstance` (и при необходимости `apiUrl`),
  приложение проверяет инстанс через `getStateInstance`, при необходимости включает
  webhook-настройки для очереди уведомлений, сохраняет креды в `localStorage` и открывает
  экран чата. Логаут стирает креды и возвращает на форму.
- Креды нужны фичам этапов 4–5 (`send-message`, `receive-messages`), а фичи не
  импортируют друг друга. Поэтому креды и логаут лежат в новом слайсе `entities/session`,
  а в `features/auth` — форма логина и кнопка логаута.
- Итог: после перезагрузки страницы залогиненный пользователь сразу видит экран чата
  (заглушку, наполняется на этапе 4); `make check` зелёный.

## Development Approach

- **testing approach**: Regular (код, затем тесты в той же задаче)
- каждую задачу завершать полностью до перехода к следующей; коммит на каждую задачу
- **CRITICAL: каждая задача с кодом включает новые/обновлённые тесты**
- **CRITICAL: каждая задача заканчивается зелёным `make check`**
- **CRITICAL: обновлять этот план при изменении скоупа**
- API Reatom (`reatomForm`, `onSubmit`, `abortVar`, `withLocalStorage`, `bindField`)
  сверять по skill `reatom`/`reatom-async` и `.d.ts` в `node_modules`, не по памяти.
  Расхождения с планом — ⚠️ в плане.
- YAGNI: не делать `greenApiAtom`, очистку чатов/сообщений при логауте, логаут по `401`
  из polling, роутер — это этапы 4–5. Экран чата — только заглушка с кнопкой логаута.

## Solution Overview

```
app          — выбор экрана: credentialsAtom() ? <ChatPage/> : <LoginPage/>
pages/login  — LoginPage: центрированная карточка с LoginForm
pages/chat   — ChatPage: заглушка с шапкой и LogoutButton (наполняет этап 4)
features/auth
  model      — loginForm (reatomForm), ensureNotificationSettings, loginErrorMessage
  ui         — LoginForm, LogoutButton
entities/session
  model      — credentialsAtom (persist "ga.credentials"), logout
```

- **Навигация** — условный рендер в `app` по `credentialsAtom`. Экранов два, роутер избыточен.
- **Форма** — `reatomForm`. Логин целиком — в `onSubmit`: при повторном сабмите
  предыдущий отменяется, `submit.ready()`/`submit.error()` дают лоадер и ошибку.
  Mantine только отрисовывает: `<TextInput {...bindField(field)} />`.
- **Креды сохраняются только после успешной проверки** — до этого живут в полях формы.
  Экран переключается сам после `credentialsAtom.set(...)`.
- **Настройки** — автоматически: одним `setSettings` включаем выключенные флаги и очищаем
  непустой `webhookUrl`, затем тост про ~5 минут. Ошибка на этом шаге логин не блокирует —
  только предупреждающий тост. Отмена (`isAbort`) пробрасывается всегда.
- **`logout` в `entities/session`**, а не в фиче: на этапе 5 его вызовет
  `receive-messages` при `401`/`403`.
- ⚠️ **Временное исключение steiger.** `fsd/insignificant-slice` (из `recommended`) роняет
  `make lint-fsd`, пока у слайса нет потребителей: `entities/session` без импортёров или
  с одним `features/auth`, `features/auth` без страниц (проверено ревью плана на копии
  репозитория). В Task 1 в `steiger.config.ts` добавляется override
  `{ files: ["./src/entities/session/**", "./src/features/auth/**"], rules:
  { "fsd/insignificant-slice": "off" } }` с комментарием-причиной; в Task 5, когда `app`
  и страницы подключат слайсы, он удаляется.
- **После успешного логина поля формы очищаются** (`resetOnSubmit: true`), чтобы токен не
  оставался в состоянии формы; после «Выйти» форма пустая.

## Technical Details

### `entities/session`

```ts
// src/entities/session/model/session.ts
export const credentialsAtom = atom<Credentials | null>(null, "session.credentials")
  .extend(withLocalStorage("ga.credentials"));

export const logout = action(() => {
  credentialsAtom.set(null);
}, "session.logout");
```

- Сверено по `node_modules`: `withLocalStorage` принимает строку-ключ или объект
  `{ key, version, migration, … }`. `version`/`migration` добавим, когда формат изменится.
- `set(null)` не удаляет ключ, а пишет запись с `data: null`: токена в хранилище нет, этого
  достаточно.
- `subscribe` по умолчанию `true`: логаут в одной вкладке разлогинивает остальные.
- Битый JSON в хранилище → адаптер ловит ошибку и возвращает начальное `null` (пишет
  `console.warn`).

### Поля формы и валидация

| поле | правило | ошибка |
| --- | --- | --- |
| `idInstance` | обязательно, после `trim` только цифры | «Введите idInstance (только цифры)» |
| `apiTokenInstance` | обязательно, после `trim` непустой | «Введите apiTokenInstance» |
| `apiUrl` | необязательно; если пусто и `resolveApiUrl(idInstance)` → `undefined` — ошибка; если заполнено — `http(s)://…` | «Укажите apiUrl из консоли GREEN-API» / «Некорректный URL» |

- Итоговый `apiUrl` = `apiUrl.trim()` (без завершающего `/`) или `resolveApiUrl(idInstance)`.
- Плейсхолдер поля `apiUrl` показывает вычисленный адрес (`resolveApiUrl(idInstance)`),
  чтобы было видно, куда пойдёт запрос.
- Правила — в `reatomField("", { validate })` каждого поля. Поле `idInstance` создаётся
  отдельным `reatomField` до формы, и `validate` поля `apiUrl` читает его напрямую
  (`fields.idInstance` при объявлении полей ещё нет). Имя формы — опция
  `name: "auth.loginForm"`. Опция формы `validate` устарела — не использовать.
- `keepErrorOnChange: false`: ошибка поля исчезает, как только пользователь начал его
  править (по умолчанию она висит до следующего сабмита).

### Поток `onSubmit`

1. Собрать `creds: Credentials` из полей (trim) и `api = createGreenApi(creds)`.
   `signal` берётся через `abortVar.subscribe()` в `try { … } finally { unsubscribe() }`
   (без `using`). `onSubmit` выполняется в кадре `submit`, поэтому повторный сабмит и
   `submit.abort()` отменяют запросы. Все `await` — через `wrap(...)`.
2. `getStateInstance` → `stateInstance !== "authorized"` → бросить `LoginError` с текстом
   по состоянию (см. таблицу ниже).
3. `ensureNotificationSettings(api, { signal })` → `"ok" | "updated" | "failed"`:
   - `getSettings`; патч = выключенные из `incomingWebhook`, `outgoingMessageWebhook`,
     `outgoingAPIMessageWebhook` → `"yes"`, плюс `webhookUrl: ""`, если не пуст;
   - патч пуст → `"ok"`; иначе `setSettings(patch)` → `"updated"`;
   - `ApiError` (любой `kind`) → `"failed"`; отмена (`isAbort`) и прочее — пробросить.
4. `credentialsAtom.set(creds)`.
5. Тост: `"updated"` → «Настройки инстанса обновлены. Входящие сообщения начнут приходить
   в течение ~5 минут»; `"failed"` → предупреждение «Не удалось проверить настройки
   инстанса — входящие могут не приходить».

Тосты вызываются из модели через `notifications.show` (`@mantine/notifications`) —
после `credentialsAtom.set` форма размонтируется, и UI уже не сможет отреагировать.

### Тексты ошибок (`loginErrorMessage(error)`)

| причина | текст |
| --- | --- |
| `LoginError` (`notAuthorized`, `pendingPassword`) | «Инстанс не авторизован в Telegram» |
| `LoginError` (`blocked`, `suspended`) | «Инстанс заблокирован или приостановлен» |
| `LoginError` (`starting`) | «Инстанс запускается, попробуйте через минуту» |
| `ApiError` `auth` | «Неверный idInstance или apiTokenInstance» |
| `ApiError` `network` | «Нет связи с GREEN-API. Проверьте apiUrl и подключение» |
| `ApiError` `http` | «Ошибка GREEN-API (HTTP {status})» / без `status` — «Некорректный ответ GREEN-API» |
| `ApiError` `rate-limit` (`469`) | «Слишком много запросов, попробуйте позже» |
| прочее | «Не удалось войти» |
| отмена (`isAbort`) | ошибку не показываем |

Если поля не прошли валидацию, `reatomForm` кладёт в `submit.error()` обычный `Error`.
`Alert` для него не показываем: ошибки уже видны у полей. `Alert` выводится только для
`ApiError`/`LoginError` и когда `loginForm.validation().errors` пуст.

`LoginError` — локальный класс фичи (`class LoginError extends Error` с полем `state`;
без parameter properties из-за `erasableSyntaxOnly`).

### UI

- `LoginForm` (`reatomComponent`): `TextInput` idInstance, `PasswordInput`
  apiTokenInstance, `TextInput` apiUrl (плейсхолдер — вычисленный адрес, описание «Можно
  не заполнять»), `Button type="submit" loading={!submit.ready()}`. Во время запроса поля
  заблокированы (`<fieldset disabled>` или `disabled` у полей). Ошибка — `Alert` с
  `loginErrorMessage(submit.error())`.
- `LogoutButton` (`reatomComponent`): `Button variant="subtle"` «Выйти» → `logout()`.
- Обработчики событий — через `wrap` (из-за `clearStack()` иначе «missing async stack»):
  `onSubmit={wrap((e) => { e.preventDefault(); loginForm.submit(); })}`,
  `onClick={wrap(logout)}` (или `useWrap`/`useAction`).
- `LoginPage`: заголовок «GREEN-API chat» + `LoginForm` по центру (CSS Module).
- `ChatPage`: шапка с заголовком и `LogoutButton`, тело — заглушка «Чаты появятся здесь».
